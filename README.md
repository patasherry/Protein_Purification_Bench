# Protein Purification Bench

Protein Purification Bench is a single-file browser application for making publication-quality protein purification figures: HPLC and ÄKTA chromatograms, SDS-PAGE gels with densitometry, size-exclusion (SEC) calibration, NanoDrop readings and spectra, construct schematics, and composite multi-step purification workflow figures with a quantitative summary table and draft Methods text.

## How to use

Double-click `protein-purification-bench.html` to open it in any web browser (or add `#quick` to the URL to jump straight into Quick-Figure mode).

**1. Quick figure from one chromatogram**
Click **"Make a quick figure without a project"** on the home screen. Drop a CSV, TSV, TXT, or UNICORN 7 `.zip` file from the ÄKTA or HPLC (or paste two columns from Excel). Drag across the chart to integrate a peak, or click **"Detect peaks"** under Peak integration. Copy the SVG or save a PNG at journal column widths.

*   **Zoom inset and Zoom mode (HPLC overlay, ÄKTA run chart, and workflow panels):**
    *   *What it does:* **Zoom inset** displays the complete recorded chromatogram on the main plot while magnifying a selected retention or elution window in a secondary plot with independent axes, a shaded source box, and orthogonal connector lines. On ÄKTA runs without an explicit zoom window, it automatically magnifies the pooled fractions (or active elution peak) against the full run. In-plot insets automatically avoid peaks, `%B`/conductivity traces, pooled-fraction shading, SEC markers, labels, and legends—and expand main-plot headroom when peaks span every corner. In the workflow figure an automatically placed panel inset takes the largest size that fits in open space (about half the plot width), names its unit across the top of its axis instead of a rotated title so the magnified data keeps the width, and does not repeat the pool caption; its connector leaders step around peak labels instead of crossing them—while **Above (callout panel)** and **Beside (right)** place the magnified view completely outside the main plot area so nothing on the full chromatogram is ever covered. **Zoom mode** switches chart click-and-drag interaction from adding an integration peak to interactively setting the magnified window.
    *   *Where to find it:* In the side panel under the **Window** section (or **Show Inset View** on a selected workflow panel's toolbar). Tick **"Zoom mode: drag on figure to select window"** to drag-select the window directly on the plot. Tick **"Show Inset View: whole run, with the X window magnified"** to display the inset, with options for position (upper right, upper left, lower right, above callout panel, beside right), relative size, and interactive drag/resize handles.
    *   *Tip:* Use **Above (callout panel)** or **Beside (right)** on crowded chromatograms to keep 100% of the overview trace unobstructed, or drag any in-plot inset directly on the figure (hold `Shift` while dragging a corner handle to unlock aspect ratio). (Presentation only: peak areas, integration, SEC masses, and yields do not change).
*   **Settings panel (More options and settings search):**
    *   *What it does:* Each section shows common settings first. Rarely changed options (such as line width, font family, smoothing points, label decimals, integration prominence threshold) sit inside a collapsed **More options** fold at the bottom of that section. A live search box at the top filters controls by label and automatically expands parent sections and disclosure folds to display matches.
    *   *Where to find it:* At the top of the side panel: **Search settings/data/files** (`#panelSearch`). At the bottom of each settings group: **More options** (`details.more`).
    *   *Tip:* Any setting modified from its default value is automatically kept visible—its section's More options expands automatically and stays open across project saves and reloads.
*   **iOS-style look and dark mode:**
    *   *What it does:* The web application features an iOS-inspired interface with inset grouped card sections, smooth toggle switches, segmented controls, tactile button feedback, and system typography (`-apple-system`, `SF Pro Text`, `Instrument Sans`). It automatically adapts to dark mode based on operating system appearance (`prefers-color-scheme: dark`) or explicit theme attributes.
    *   *Where to find it:* Active across the entire web application interface. Dark mode triggers automatically when your system or browser is set to dark theme.
    *   *Tip:* The iOS styling and dark theme apply strictly to the web application shell and controls; the figure preview and exported SVGs/PNGs always preserve publication styling (Arial font, white background, standard palettes) so exports remain journal-ready.

**2. A full purification project**
From the home screen, enter a project name and click **"Start project"**. Use the **Steps** timeline on the left to record each stage of your prep: construct, transformation, expression, lysis, every chromatography column, concentration/NanoDrop checks, protease cleavage/dialysis, any gravity or batch steps without a chromatogram, and the final sample. For each column run, type fraction names (such as `T3-T6`, `T5#2` for a wrapped rack, or `A1-A6` for 96-well plates) or click **Suggest** to mark the pool. Drop in gel images and NanoDrop exports as you go. The workflow figure, purification summary table, and Methods text update automatically.

*   **Front-page project folders and organization:**
    *   *What it does:* Provides a toolbar directly above the front-page project list with **New Project**, **New Folder**, **Move**, **Rename**, **Archive** (with restoration), **Search**, **Sort**, and **List/Grid View**, paired with a collapsible folder tree, clickable breadcrumb navigation, and a main contents view where folders are visually distinct from projects. Supports nested subfolders (preventing circular nesting), dragging projects or folders into folders or back to the top level, multi-selecting projects to move or archive together, and renaming items without opening them.
    *   *Where to find it:* Directly on the app's front page (`#home`, reachable anytime via **All projects** `#homeBtn`).
    *   *Tip:* Existing projects stay at the top level until organized, the complete folder hierarchy is saved and restored automatically when reopening the app, and moving or renaming a project on the front page never alters its workflow, results, attachments, or sample lineage.
*   **Project Explorer (folders, multiple preparations, and file attachments):**
    *   *What it does:* Organizes each project with a File Explorer-style directory supporting folders and nested subfolders, multiple independent protein preparations (each keeping its own cloning, construct, sequence/$\varepsilon_{280}$, expression, purification runs, gels, NanoDrop readings, structures, figures, and lineage), and uploaded experimental attachments. Supports collapsible folder-tree navigation, breadcrumbs, live search, sorting, list and grid views, rename, move (preventing circular folder nesting), preparation duplication, drag-and-drop, and safe archive-before-delete with full restoration.
    *   *Where to find it:* In the project header bar, click **Explorer** (`#openDirBtn`) or any folder/preparation breadcrumb (`#projDirCrumbs`).
    *   *Tip:* Every folder and preparation uses a stable internal ID, so renaming or moving a preparation or folder never breaks links or duplicates records, and existing single-preparation project files open seamlessly.
*   **Full chromatogram and full uncropped gel in the workflow:**
    *   *What it does:* **Full chromatogram in the workflow** draws each chromatography column in the workflow figure over its entire recorded run range rather than cropping to the run's individual retention window (`xmin` / `xmax`). **Full uncropped gel in the workflow** shows each step's assigned gel lanes over their full top-to-bottom height under the chromatogram (disabling the vertical main-band focus crop while keeping lane labels, kDa markers, and fraction connector lines aligned). Single-run figures keep their zoomed chromatogram window and **Gel view** setting.
    *   *Where to find it:* In the side panel under **Purification workflow** $\rightarrow$ **Figure options**, tick **"Full uncropped gel in the workflow"** (`#o-wfGelFull`) and/or **"Full chromatogram in the workflow"** (`#o-wfFull`).
    *   *Tip:* This lets you keep focused peak windows and main-band gel views on individual run figures while displaying the complete purification run and full top-to-bottom gel lanes in the main workflow figure.
*   **Margin under text panels:**
    *   *What it does:* In the **Stacked** workflow layout, a step without a chromatogram (expression, lysis, cleavage, a gravity or batch step) is drawn only as tall as its own text plus this margin, instead of being given a whole chromatogram's height. Its gel, and the step after it, then follow closely. Leave the field empty for the automatic margin of 0.8 x the figure font size. The margin is never allowed below 0.35 x the font size, so text cannot touch what comes next.
    *   *Where to find it:* In the side panel under **Purification workflow** → **Figure options** → **Panel geometry and labels (optional)**, **"Margin under text panels (pt)"** (`#o-wfPad`).
    *   *Tip:* Raise it to open the figure up when a stacked workflow looks crowded. The same margin sets how much room is left under the text in the upstream band, so it has an effect in every layout; only the content-fitting above is specific to **Stacked**.
*   **Step schematics for non-chromatogram stages:**
    *   *What it does:* Steps without a chromatogram, gel densitometry plot, or NanoDrop UV spectrum—Transformation, Expression, Lysis (auto-selecting sonication, high-pressure homogenization, or chemical lysis), Dialysis and protease cleavage, between-column transfers (spin concentration, dilution, desalting/buffer exchange, membrane filtration, overnight hold), manual steps (gravity column, batch capture, precipitation, custom), and Final sample cryostorage—are illustrated with self-contained Okabe-Ito vector schematics bound strictly to the values you entered (falling back to neutral labels when left blank).
    *   *Where to find it:* Drawn automatically on each step's own figure and in the workflow figure; optional **Transformation panel** (`#pr-transform`) and **Final sample panel** (`#pr-finPanel`, under **Quality and characterization checks**) checkboxes include those stages in the composite workflow figure while keeping legacy saved projects unchanged.
*   **OD₆₀₀ growth monitoring (Expression step):**
    *   *What it does:* Records culture $\text{OD}_{600}$ time-series readings by manual entry, multi-culture CSV/TSV import, or NanoDrop 600 nm / full-spectrum export attachment, automatically computing $\text{corrected OD}_{600} = \text{raw OD}_{600} \times \text{dilution factor}$ while preserving raw values, dilution factors, blanks, instrument/operator metadata, event markers (inoculation, induction, temperature shift, sampling, harvest), and notes. Plots measured points with straight line segments per culture (no smoothing, extrapolation, inferred growth phases, or unmeasured error bars), links induction $\text{OD}_{600}$ and harvest sample records to the Expression step, and displays full absorbance spectra with a `600 nm` reference line only when real spectral data are attached.
    *   *Where to find it:* On the **Expression** step under **OD₆₀₀ growth monitoring** (`#odGrowthSec`), with **Import CSV**, **Attach NanoDrop**, **Export CSV**, and **Show in figure** (`#odFigBtn`) for standalone SVG/PNG export.
*   **Dragging panels and Reset position:**
    *   *What it does:* Lets you interactively drag panels in the workflow figure to fine-tune layout and spacing. The connecting arrows between panels follow dynamically with angled heads, and the figure canvas expands so nothing is cut off. Moves are saved with the project file and applied to SVG/PNG exports.
    *   *Where to find it:* In the workflow figure, click any panel to select it (opens the floating panel toolbar), then drag it to your desired position. Click **Reset position** in the panel toolbar to restore the panel to its default calculated position.
    *   *Tip:* Movements under 4 px count as selection clicks rather than drags, preventing accidental shifts when clicking to select a panel. (Presentation only: does not change calculated masses, areas, or yields).
*   **Parallel branches and per-branch yields:**
    *   *What it does:* Models branched purification schemes where an intermediate pool is split across different downstream purification steps (e.g., splitting an IMAC pool between SEC and anion exchange). Steps coming from the same step are drawn as branches with forked connecting arrows. The app tracks independent purification branches, computes separate final yields for each branch terminus, and details the split and individual pool yields in the generated Methods text and purification summary table.
    *   *Where to find it:* Open a step in the **Steps** timeline $\rightarrow$ in the step details sheet, set **Comes from** (`#ssFrom`) to an earlier step, with an optional **Which fraction or pool** note (`#ssFromNote`). Under figure options, tick **Yield line** (`#o-wfYield`) to display final yield summaries below the workflow figure.
    *   *Tip:* Use the "Which fraction or pool" note (e.g. `fractions B5-B8`) to label the arrow fork; this note automatically formats into the Methods text describing which fractions fed into each downstream step.
    *   *How it changes reported numbers:* Instead of assuming a single sequential linear prep with one overall final yield, parallel branches evaluate recovery yields against the specific parent pool load for each branch and report independent final yields (protein mass in mg, volume, concentration, and recovery %) for each terminal branch.

**3. SEC calibration**
Open the **Size exclusion (SEC)** section and tick **"Size peaks with calibration standards (apparent MW, Kav, oligomer state)"**. Choose a standard kit (Bio-Rad, Cytiva HMW/LMW, or custom), drop a standards run file, select it under **"Read standard volumes from"**, and click **"Read peaks"** to review and confirm the peak-to-standard matching. The app fits $\log_{10}(\text{MW})$ against $K_{\text{av}}$ (or $V_e$) and labels SEC peaks with apparent molecular weight or oligomer state.

**4. Gels**
Drop a PNG, JPEG, or TIFF gel image. The app automatically crops to the stained lanes, tracks lane tilt, matches the ladder lane (default: Bio-Rad Precision Plus; change the **Ladder** menu if you used another marker) to calibrate band sizes, and integrates bands in each lane. Lanes named after fractions (`T3`, `Pool`, `Lysate`, `-Ulp1`/`+Ulp1`) are automatically linked to their run or prep step, with optional connector lines and color-coding between chromatogram fractions and gel lanes. Click bands (or cycle their chips in the band table) to mark **Target**, **Tagged**, or **Contaminant** bands for purity and molar cleavage calculations.

**5. Protein, Construct, and PDB structures**
In the **Protein** section, paste your untagged protein sequence or load a 4-character PDB code (or drop a `.cif`/`.pdb` file). The app calculates chain masses, Bjellqvist pI (matching ExPASy ProtParam), and reduced $A_{280}$ (1 mg/mL) values for the tagged, cleaved, and free-tag forms. Clicking **"Use for gel, SEC and mg"** applies these values across gel band matching, SEC monomer sizing, and UV/NanoDrop mg calculations. Dropping a GenBank file (`.gb`, `.gbk`, `.ape`, `.dna`) draws a scaled expression cassette schematic showing the promoter, operator, RBS, tag, protease site, ORF, and terminator.

*   **Paste GenBank text:**
    *   *What it does:* Imports plasmid DNA sequences and annotations by directly pasting plain text in GenBank flat file format (e.g. copied from Benchling, SnapGene, or NCBI) without needing to save to an intermediate `.gb` file on disk. Parses CDS annotations, affinity tags, protease cleavage sites, and translates the target ORF.
    *   *Where to find it:* Under **Construct, expression and cleavage** $\rightarrow$ **Construct**, click **Paste GenBank text**, paste the text into the box, and click **Use pasted text**.
    *   *Tip:* Only DNA records are accepted; protein records and FASTA files are rejected with an informative toast message. When pasting text containing multiple concatenated records, only the first record is read.
*   **Tagged samples without a tag sequence:**
    *   *What it does:* When a tag preset lacking a built-in sequence (such as GST or MBP) is chosen in the Construct or Protein section, but the specific tag sequence has not yet been provided, the app withholds the extinction coefficient ($\varepsilon_{280}$) for tagged steps instead of erroneously applying the untagged target protein's extinction coefficient.
    *   *Where to find it:* In the **Protein** section under Tag settings (`#o-tagPreset2`), or in the Construct panel when selecting a tag preset.
    *   *Tip:* If you do not have the tag sequence at hand, you can type a manual extinction coefficient under **Peak integration** ($\varepsilon_{280}$) to report protein masses and concentrations immediately.
    *   *How it changes reported numbers:* Changes reported numbers by withholding (leaving blank) protein mass and concentration values for pre-cleavage samples until either the fusion tag sequence or a manual extinction coefficient is provided, preventing erroneous masses based on untagged extinction coefficients.

**6. Exports and backups**
Below the figure, click **"Copy SVG"**, **"Save SVG"**, **"Save PNG"** (at 300, 600, or 1200 dpi), or **"Save all (ZIP)"** to bundle all figures and CSV tables. Below each table, click **"Save table (CSV)"** or **"Copy methods"**. In the top bar, click **"Export file"** to download a `.json` backup of your project, **"Open file"** to load a saved `.json` project, or **"Save as project"** to turn a quick figure into a saved project.

**7. Troubleshooting**
Status messages and hints explain missing inputs or unverified numbers. For example, if UV protein mass cannot be calculated for a run, the summary notes explain why—such as `"the x axis is in minutes and the flow rate is not known (enter it under Flow)"` or `"the selected UV curve is 260 nm, not 280 nm"`.

## Plain traces inside a project

A file with only time and signal columns, such as an analytical HPLC export, is an overlay trace and not a purification run: it has no fractions or pools. When you load one into a project it gets its own step, **HPLC traces**, in the step list. That step shows every plain trace of the project as one overlay and lists their cards. Removing the last trace removes the step.

## Cloning workflow

The new-project form has one switch, **Include Cloning**. It is off for a new project and answers to a click, Space or Enter.

- **Off** opens the project at the construct and expression steps, as before. The Transformation step gains a short record of where the plasmid came from. A construct is recorded as sequence verified only when you say how it was verified.
- **On** adds a **Cloning** group at the top of the step list. Choose a workflow there: Around-the-Horn mutagenesis, gBlock-to-pDEST HiFi assembly, PCR-based plasmid cloning, or a custom one. Its stages appear as steps, folded so a long workflow does not push the rest of the project out of sight: the step list shows the stage you are on, the next one to do, any stage with a flag, and one **N done** row for the finished ones. **Show all stages** lists every stage until you fold them again. Mix and Go competent-cell preparation can be added to any project from **Add a stage**. The cloning steps feed the rest of the project, so the plasmid is entered once: a sequence-verified clone fills the plasmid at **Transformation** and the plasmid name at **Construct**, unless you typed something else there. The transfer to expression (which clone, and whether it was sequence verified) is recorded at **Transformation**, whose Plasmid, Strain and Selection fields it uses, and the cloning-strain step is called **Cloning transformation** to keep the two apart. Projects saved earlier keep every value: an older transfer record fills empty Transformation fields, and a value that differs is kept in that record's notes. With cloning on, the Expression step is flagged until the clone used for expression is named: select it at Transformation, or mark the transfer to expression done there.

Each stage keeps a list of attempts. An attempt has a status, a date, an operator, the attempt it comes from, the stage's own fields, deviations and notes. A failed attempt stays in the record when you repeat the step, and a stage can be skipped, moved or duplicated. The miniprep and competent-cell stages carry a checklist and the source recipe as a reference line.

The app does not calculate or fill in any cloning value. It only flags records that are incomplete: a selected PCR product with no gel lane, a KLD or HiFi reaction with no input, a colony with no transformation, a transformation with no competent-cell batch, a clone marked verified with no completed sequencing record, a batch marked Qualified with no competency test, and a harvest OD600 outside 0.4 to 0.6. A flagged stage is not shown as done.

The **Cloning workflow** step shows the lineage of the whole record as text, with a button to copy it, and completed cloning stages write a concise cloning paragraph into the generated **Methods** text whenever **Include Cloning** is on. **Project settings** in the project header (and on a phone, the Cloning workflow or Transformation step) holds the **Include Cloning** switch and, whenever cloning stages are archived, a **Restore Cloning Workflow** button. Switching **Include Cloning** off confirms archival when stages exist, hides the cloning steps, their flags and the cloning lines in the Methods, updates active step progress to exclude archived cloning stages, and keeps every stage, attachment and downstream construct/expression link for when cloning is restored. It is saved with the project as `includeCloning`. A project saved before the switch existed opens with it on if it holds any cloning record, and off if it does not.

**Agarose-gel verification** stages accept PNG, JPEG, and TIFF gel images with non-destructive crop, rotation, brightness, and contrast adjustments (plus **Replace image** and **Restore original**), an interactive lane editor with auto-detection, DNA ladder fragment presets and $\log_{10}(\text{bp})$ migration calibration, a band table comparing expected and observed sizes, and a **Generate figure** view for publication-ready DNA gel panels.

Not built yet: calculators (primer dilution, molar ratios, recipe scaling), general file attachments on non-gel stages, separate planned and actual values, and competent-cell batches shared between projects.

## Supported Inputs and Exports

**Inputs:**
*   **Chromatography Data:** `.csv`, `.tsv`, `.txt`, `.zip` (UNICORN 7 result archives), `.asc`, `.dat`, `.arw`, `.xy`, and pasted spreadsheet columns.
*   **Gel Images:** PNG, JPEG, and TIFF (`.tif`, `.tiff`, with built-in offline decoding for uncompressed and Deflate 8/16-bit TIFFs and on-demand `pako`/`UTIF` loading for LZW or specialized TIFFs).
*   **Sequences & Plasmids:** GenBank and plasmid files (`.gb`, `.gbk`, `.genbank`, `.ape`, `.dna`) and plain amino acid sequences. GenBank text copied from Benchling or SnapGene can be pasted with **Paste GenBank text** in the Construct section. Only the first record is read; FASTA and protein records are refused, and a LOCUS length that differs from the sequence gives a warning.
*   **Structures:** Local `.cif`, `.mmcif`, `.pdb`, `.ent` files, or live fetches from RCSB PDB by entry code.
*   **NanoDrop Readings:** `.csv`, `.tsv`, and `.txt` exports from NanoDrop One, 2000, or 8000 (Protein A280, A205, Proteins & Labels, and full spectra), or manual readings via **"Type a reading"**. The parser automatically handles vendor preamble lines (such as `"Vendor: Agilent"` or metadata labels ending with `:`) and strips status characters or asterisks on numeric values (e.g. `0.05A`, `1.23*`). Readings are checked for $A_{340}$ turbidity and light scattering, $A_{280}/A_{260}$ ratios outside `1.5–2.5` for purified protein, tied step-name matches (left unassigned for review), and unrecognised concentration units (kept as read and withheld from step mass totals until reviewed).
*   **OD₆₀₀ Growth Monitoring:** Manual time-series readings, `.csv`/`.tsv`/`.txt` culture growth tables, and NanoDrop 600 nm or full-spectrum absorbance exports on the **Expression** step.
*   **Enzyme Activity Assays:** `.csv`, `.tsv`, and `.txt` plate-reader or spreadsheet tables, pasted columns, or direct entry in the **Activity assays** panel across four modes: purification step tables (`steps`), chromatogram fraction profiles (`fractions`), steady-state substrate kinetics (`kinetics`, fitted by Levenberg–Marquardt nonlinear regression to Michaelis–Menten, Hill, or Haldane substrate-inhibition models), and pH/temperature/condition profiles (`profile`). Converts optical rates ($\Delta A/\text{min}$) via Beer–Lambert with quadrature blank subtraction into IUBMB units ($\text{U/mL}$, $\text{U}$, $\text{U/mg}$) and SI katals ($\text{nkat/mL}$, $1\text{ U} = 16.67\text{ nkat}$).
*   **Project Files:** `.json` project files exported from this tool. Damaged or incomplete entries are skipped with a count. Spreadsheets (`.xlsx`) and HEIC/PDF images are not read directly; export them as CSV or PNG/JPEG/TIFF first.

**Outputs:**
*   **Figures:** SVG (clipboard or file), PNG (300, 600, or 1200 dpi), or a combined ZIP archive (**"Save all (ZIP)"**) of all figures and CSV tables, including aligned chromatogram fraction-activity tracks/overlays, $\text{OD}_{600}$ growth curves and spectra, and standalone or workflow activity panels.
*   **Tables & Text:** Purification summary CSV (with total activity, specific activity, purification fold, split-adjusted activity yield, and apparent $k_{\text{cat}}$ when assays are recorded), $\text{OD}_{600}$ growth monitoring CSV, peak integration CSV, gel band densitometry CSV, and generated STRENDA-aligned Methods and Results text.
*   **Raw Files:** Files uploaded inside a project (ÄKTA, HPLC, NanoDrop, gel images) are kept as uploaded in the same browser database (`blobs` store), or the page's asset store when hosted. The project record holds only name, size, date and a reference. A **Raw files (n)** list in the project bar downloads or removes each one. They are not included in the exported project `.json`.
*   **Project Backups:** Single-file `.json` project exports containing all runs, traces, cropped/original gels, NanoDrop readings, activity assays, structures, steps, figure settings, and the Project Explorer folder hierarchy, protein preparations, and uploaded Explorer attachments (up to 5 MB each).

## Protein mg from the UV area and NanoDrop

*   **Formula:** $\text{mg} = \frac{A_{280}\text{ area (mAU}\cdot\text{mL)}}{1000 \times \varepsilon_{1\text{ mg/mL}} \times \text{path (cm)}}$.
*   **Step-Aware Extinction Coefficient:** When a protein sequence and tag are provided, steps up to protease cleavage use the tagged form's $A_{280}$ (1 mg/mL) and steps after cleavage use the cleaved form's $A_{280}$ (1 mg/mL). A sequence counts as tagged only when a tag preset is chosen or a tag sequence is entered: the Tag menu starts at **No tag**, so a sequence pasted on its own uses the untagged $A_{280}$ for every step. Settings and projects saved under the old His-SUMO default keep that tag. If a tag preset without a known sequence (such as GST or MBP) is selected without an entered tag sequence, the coefficient is withheld until the sequence is entered or a manual coefficient is typed. Otherwise, the single $A_{280}$ value set under Peak integration is used.
*   **Branch-Aware Yields:** In branched purification workflows, recovery yields and pool amounts are calculated along each specific branch path rather than assuming a single linear sequence. The summary table and Methods text report yields and splits per branch.
*   **NanoDrop Override and Aliquot Allocation:** When a step's pool or Concentrated step has a measured NanoDrop concentration and volume, that measured mass ($\text{conc} \times \text{vol}$) is used for the step and scales integrated peak mg estimates for peaks overlapping the pool (leaving unpooled peaks at their Beer–Lambert UV mass). If only an aliquot went on to the next chromatography step, optional **Loaded on the next step** and **Kept back** fields allow downstream step yield calculations to count from the loaded share rather than the total concentrated output.
*   **mAU Traces:** `AU` traces are automatically converted to `mAU`.
*   **Time to Volume Conversion:** Runs recorded in minutes are converted to mL using the run's flow rate (read from the file or entered under Run conditions). Without a flow rate, no UV mg is reported.
*   **A280 Wavelength:** Only 280 nm UV curves report protein mass; other wavelengths report area only.
*   **UV Path Length:** Read automatically from UNICORN 7 `.zip` archives when present; otherwise defaults to `2 mm` (standard ÄKTA pure/start flow cell) and is noted as assumed unless set on the run card (e.g., `10 mm` for HPLC).
*   **Integration Scope:** Peak and pool areas always integrate the raw recorded trace over the full run using the selected integration baseline (**Valley to valley** or **Zero (0 mAU)**), with peaks resolved either by multi-Gaussian deconvolution (default) or boundary trapezoids. Display smoothing, figure baseline drift removal, and plot zooming change only the drawn curve, never the integrated areas or mg yields.
*   **Pool Volume Calculation:** Sums pooled fraction segments from start to end markers, capping the final fraction at the logged end of fractionation (or one median fraction width) and capping fractions before tube-number gaps exceeding $1.5\times$ the median width.

## Gel measurements

*   **Auto Crop & Lane Tracking:** Automatically trims to the stained lanes between the wells and dye front, fits the lane grid across vertical segments to follow tilted or fanning lanes, and extracts background-corrected vertical profiles (rolling-minimum opening).
*   **Molecular Weight Estimation:** Matches detected ladder bands to the selected preset (or manual clicks) and interpolates sample band sizes piecewise-linearly in $\log_{10}(\text{kDa})$. Calibration requires finite marks at distinct positions with sizes decreasing top to bottom.
*   **Band Tagging & Purity:** Supports two purity denominators (**All stain in the lane** between the top 3% and bottom 2% margins, or **Target plus marked contaminants**). When no bands are manually marked, purity is estimated from bands within $\pm 8\%$ of the expected protein mass for that step. Removing a band removes its area from the lane denominator.
*   **Molar Cleavage & Expression:** Cleavage efficiency (%) is calculated on a molar basis ($\text{area} / \text{MW}$ of cleaved vs. uncleaved bands). Expression gels with `U`, `I`, `S`, and `P` lanes quantify expression level (% of induced lane) and solubility (% in `S` vs. `S + P`).
*   **Known Contaminants:** Optional size-matching against common *E. coli* IMAC co-purifiers (Bolanos-Garcia & Davies 2006) and purification additives (off by default; only plausible step contexts within the calibrated ladder range are flagged as `size ≈ Name`).
*   **Display vs. Measurement:** Dark/light contrast sliders and color settings affect the displayed image only; densitometry always reads the underlying grayscale intensities (inverted only when **Invert** is checked for light-on-dark gels).

## Import and SEC calibration

*   **SEC "Read peaks":** Once **"Size peaks with calibration standards"** is enabled, clicking **"Read peaks"** skips unticked standards, takes detected peaks in elution order within any entered $V_0 / V_t$ limits, and asks you to confirm the proposed assignment before applying it. If there are fewer peaks than standards, leftover low-MW standards are listed and their volumes are cleared so a fit never mixes two runs.
*   **Column Presets:** Superdex 75 and 200 Increase 10/300 GL (24 mL), Superose 6 Increase 10/300 GL (24 mL), Superdex 75 and 200 Increase 5/150 GL (3 mL, [Cytiva specifications](https://www.cytivalifesciences.co.jp/catalog/0063.html)), and HiLoad 16/600 (120 mL) and 26/600 (320 mL) columns are recognized by name.
*   **Decimal & Delimiter Handling:** Tab-delimited UNICORN files and pasted tables support decimal commas. NanoDrop imports treat a lone comma as a decimal point (`0,123` $\rightarrow$ `0.123`) unless followed by three digits after a nonzero number (`1,234` $\rightarrow$ `1234`). Timestamps and row positions distinguish replicates during duplicate checks.

## Storage and Backups

*   **Browser Storage:** Saves figure preferences, SEC calibrations, and custom contaminant lists in `localStorage` (`hplc-fig-opt`), and saves projects automatically in `IndexedDB` (`hfb-projects`).
*   **Host Integration:** Uses cloud database and asset storage when hosted in an environment providing `window.claude`.
*   **Project Backups:** Export and import complete projects as `.json` files via **"Export project"** and **"Open file"** (both in the header).

## External Libraries and Network Dependencies

*   **Fonts:** Instrument Sans from Google Fonts (`fonts.googleapis.com` and `fonts.gstatic.com`).
*   **TIFF Gel Support:** Built-in offline reader for uncompressed and Deflate 8/16-bit TIFFs; `pako` 2.1.0 (`cdnjs.cloudflare.com`) and `UTIF` 3.1.0 (`cdn.jsdelivr.net`) loaded on demand only when an LZW or specialized TIFF image is opened.
*   **PDB Structures:** Structure files fetched on demand from RCSB Protein Data Bank (`files.rcsb.org/download/`) when a PDB code is loaded.

## Repository Layout

*   `protein-purification-bench.html`: Single-file web application (HTML, CSS, and JavaScript).
*   `README.md`: User-facing documentation.
*   `AGENTS.md` / `CLAUDE.md`: Shared instructions and rules for coding agents.
*   `.github/workflows/`: GitHub Actions for automated browser tests and PR reviews.
*   `tests/`: Automated Playwright browser test suite and synthetic test datasets.

**A note on the name.** The app was called HPLC Figure Bench until November 2026. Exported project files still write `"app": "HPLC Figure Bench"` (while the importer accepts both `"HPLC Figure Bench"` and `"Protein Purification Bench"`), and the browser still stores settings under `hplc-fig-opt` and projects under `hfb-projects`, so everything you saved under the old name keeps working and a file you save today still opens in an older copy of the app.
